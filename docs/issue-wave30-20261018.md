# Single-owner queue to concurrent actor adapter — draft 2026-10-18

Issue #3: compare serial actor and reader/writer guarded adapters **after** single-owner native queue tests pass.

## Serial actor adapter
- Default execution-carrier min/max is (1,1), configurable independently of `requestConcurrency` and `messageConcurrency`; actor DATA turns may suspend without concurrent mutable state access.
- All guest-owned persistent fields live in exactly one `state { ... }`; no external actor fields. State access only through verified `handle_state` or `using state.read/write` lexical loans.
- Queue push/pop are messages; consumers must never call public actor implementation methods.
- Parent receives typed terminal `on_panic` / `on_raise` / `on_throw` CONTROL events, not forged user payloads.

## Reader/writer adapter
- Readers may share a stable immutable snapshot; writers require an exclusive loan. No iterator/view may outlive generation, loan or arena.
- Upgrading a held read loan to write without a defined protocol must fail rather than deadlock.
- A waiter's cancellation releases admission credit exactly once; writers cannot be indefinitely starved by continuous readers.

## Model vectors
Concurrent push/pop at empty/full boundary; duplicate key relink while reader active; shutdown racing subscription; writer fairness under 100 readers; panic cleanup during exclusive loan; generation invalidation after removal.

**Status:** architecture acceptance and adversarial cases only. No concurrent implementation or perf win is claimed.
